## `~/about-me`

I'm a **Software Engineer** with a background spanning **software development, data, machine learning and AI systems**.

I enjoy working across the stack — from writing APIs and designing databases to experimenting with ML models and figuring out why something is using 100% CPU for absolutely no reason.

I'm particularly interested in understanding **what happens underneath the abstractions**.

That means I'm not just interested in:

`What does this API do?`

but also:

`What happens after I call it?`

`How does the OS handle it?`

`Where does the data actually go?`

`What is the hardware doing underneath all of this?`

Basically, I like pulling the thread until something stops making sense.

### `01` — ResearchPilot 🔬

**Multi-Agent Research Assistance System**

A research assistant that takes a natural-language research question and turns it into an evidence-grounded technical report.

Instead of throwing everything at one LLM call, the system breaks the process into specialized agents for:

```text
Query
  ↓
Expansion
  ↓
Retrieval
  ↓
Relevance Verification
  ↓
Acquisition
  ↓
Compression
  ↓
Evidence Extraction
  ↓
Reasoning
  ↓
Report
```

**Built with**

`Python` `FastAPI` `LangChain` `LangGraph` `FAISS` `Sentence Transformers` `Ollama`

**Repository:**
`[https://github.com/chandan-athreya-s/ResearchPilot.git]`

# `./things-i-like-to-understand`

```text
┌──────────────────────────────────────┐
│                                      │
│  CPU → Memory → Bus → I/O            │
│          ↓                           │
│      Operating System                │
│          ↓                           │
│      Runtime / Process               │
│          ↓                           │
│      Application                     │
│                                      │
└──────────────────────────────────────┘
```

I have a particular interest in the layers underneath everyday software.

**Computer Architecture**
CPU, memory, storage, instruction execution, buses, caching and how hardware actually executes our code.

**Operating Systems**
Processes, threads, scheduling, memory management, filesystems, system calls and everything happening between an application and the hardware.

**Systems**
How software interacts with the machine instead of pretending the machine doesn't exist.
